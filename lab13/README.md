# Лабораторная работа №13: Паттерны проектирования и принципы SOLID в TodoListApp

## Выполнили
Лукьяненко Даниил, Мироненко Данил, группа 3831.9

## Реализация принципов SOLID
1. **SRP (Единственная ответственность):** каждый класс решает одну задачу (`TodoItem` — модель задачи, `TodoList` — управление списком, `Profile` — профиль, `FileManager` — сохранение в CSV, `CommandParser` — разбор команд).
2. **OCP (Открытость/закрытость):** новые команды подключаются через реализацию `ICommand` без изменения существующего кода парсера.
3. **LSP (Подстановка Лисков):** все команды взаимозаменяемы через вызов метода `Execute()` интерфейса `ICommand`.
4. **ISP (Разделение интерфейсов):** `ICommand` содержит только обязательный метод `Execute()`, логика отмены вынесена в `UndoableCommand`.
5. **DIP (Инверсия зависимостей):** `TodoList` отвязан от файловой системы; сохранение реализовано через подписку на события `Action<TodoItem>`.

## Использованные паттерны
- **Command:** инкапсуляция действий пользователя для реализации `undo` и `redo` на базе стеков.
- **Observer:** автоматическое сохранение данных через события изменения задач.
- **Iterator:** реализация `IEnumerable<TodoItem>` для обхода коллекции циклом `foreach`.
