## Архитектурный анализ проекта TodoListApp на основе Лекции 13

### 1. Реализованные принципы SOLID

#### 1.1 SRP — Single Responsibility Principle (Принцип единственной ответственности)
Каждый класс системы решает строго одну изолированную задачу:
- `TodoItem` отвечает за хранение и модификацию состояния одной задачи;
- `TodoList` отвечает за управление коллекцией задач (добавление, удаление, поиск, индексация);
- `Profile` представляет профиль и персональные данные пользователя;
- `FileManager` инкапсулирует операции ввода-вывода и сериализации в файлы формата CSV и Text;
- `CommandParser` отвечает исключительно за синтаксический разбор команд и маппинг на делегаты;
- Классы команд (`AddCommand`, `DeleteCommand` и др.) инкапсулируют бизнес-логику конкретных действий пользователя.

#### 1.2 OCP — Open/Closed Principle (Принцип открытости/закрытости)
Архитектура открыта для расширения, но закрыта для модификации:
- Для добавления новой пользовательской команды не требуется изменять логику метода `Parse`. Достаточно объявить новый класс команды, реализующий `ICommand`, и зарегистрировать его метод разбора в словаре делегатов `_commandHandlers`.

#### 1.3 LSP — Liskov Substitution Principle (Принцип подстановки Барбары Лисков)
- Все классы команд взаимозаменяемы через полиморфный интерфейс `ICommand`. Главный цикл приложения работает с абстракцией `ICommand` и вызывает метод `Execute()`, гарантируя корректное выполнение любой команды.

#### 1.4 ISP — Interface Segregation Principle (Принцип разделения интерфейса)
- Интерфейс `ICommand` содержит только обязательные методы жизненного цикла (`Execute()`, `Unexecute()`), не обременяя клиентов лишними контрактами. Специализированные варианты вынесены в базовый класс `UndoableCommand`.

#### 1.5 DIP — Dependency Inversion Principle (Принцип инверсии зависимостей)
- Доменная модель `TodoList` полностью отвязана от инфраструктурного слоя `FileManager`. Связь между ними инвертирована через C#-события (`OnTodoAdded`, `OnTodoDeleted`, `OnTodoUpdated`, `OnStatusChanged`), на которые внешний слой подписывается независимо.

### 2. Реализованные паттерны GoF

1. **Команда (Command)**:
   - Интерфейс `ICommand` и конкретные классы инкапсулируют запрос в виде объекта, поддерживая историю выполнения и операции отмены (`Undo`) и повтора (`Redo`).
2. **Наблюдатель (Observer / C# Events)**:
   - События в `TodoList` оповещают подписчиков (`FileManager`) об изменении данных без жесткого связывания.
3. **Итератор (Iterator)**:
   - Реализация интерфейса `IEnumerable<TodoItem>` с использованием ключевого слова `yield return` позволяет обходить элементы коллекции стандартным циклом `foreach`.
